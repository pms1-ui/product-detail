# 카카오 톡딜 상세페이지 제작

아웃도어프로덕츠 카카오 톡딜 묶음상품 상세페이지를 **회차별**로 제작하는 프로젝트입니다.
(예: 260806, 260903, ... 회차 = 진행 날짜)

배포: Netlify (`product-detail-ms.netlify.app`) · 이미지: S3 CDN (`img.childy.kr` = `aws-childy-image` 버킷)

---

## 작업 흐름 (신규 회차 만들 때)

### 1단계 — 최초 생성 (회차당 딱 1회)
1. `_작업소스/{회차}/` 폴더를 만들고 `상품이미지/`에 상품 사진을 넣는다.
2. 데이터 엑셀을 준비한다 (컬럼: 순서·년도·시즌·모델번호·모델_컬러·컬러코드·품목명·택가·톡딜가·혜택가·최종할인율).
3. generate 스크립트를 해당 회차에 맞게 복제·수정한 뒤 **저장소 루트에서** 실행:
   ```bash
   node _스크립트/generate_{회차}.mjs
   ```
   → `_작업소스/{회차}/작업용.html`이 생성된다.

### 2단계 — 부분 수정 (요청 올 때마다) ★중요
- **generate 스크립트를 다시 돌리지 않는다.** (다시 돌리면 그동안의 수동 수정이 전부 사라짐)
- `_작업소스/{회차}/작업용.html`을 **직접 편집**한다. 요청받은 구성(카드)만 수정.
- 상품명·가격이 여러 카드에 중복될 수 있으니, 반드시 "구성 NN" 위치를 기준으로 해당 카드 안에서만 수정.

### 3단계 — 카드 이미지 재생성
```bash
node _스크립트/capture_{회차}_v2.mjs
```
→ `_작업소스/{회차}/캡처결과/cards/01~98.jpg` 갱신.

### 4단계 — 로컬 확인
`미리보기/{회차}_로컬확인.html`을 브라우저로 열어 확인.

### 5단계 — S3 업로드 (배포)
`_작업소스/{회차}/캡처결과/cards/`의 jpg들을 S3에 업로드:
```
s3://aws-childy-image/img/outdoor2026/promotion/{회차서버폴더}/cards/
```
- 부분 수정 시엔 보통 `cards/`만 다시 올리면 됨.
- 상세 이미지(`detail_image/`)는 기존 S3 파일을 재사용 (새로 안 올림).
- 상세 HTML은 `img/.../kakao_detail/`에 있으며 Netlify로 배포됨.

### 6단계 — 회차 목록 등록
`index.html`에 해당 회차 카드(미리보기 링크)를 추가.

## 핵심 원칙 (반드시 지킬 것)

- **생성과 수정을 분리**: 최초 1회만 엑셀→generate. 이후 수정은 `작업용.html` 직접 편집.
- **Source of truth = 작업용.html** (엑셀은 생성 후 삭제되므로, 엑셀과 안 맞아도 정상).
- **`img/` 폴더명 변경 금지**: 서버 경로와 똑같아야 배포됨.
- **상대경로 주의**: `작업용.html`(로고 `../공용에셋/`, 상품 `상품이미지/`), `미리보기/*_로컬확인.html`(카드 `../_작업소스/.../캡처결과/cards/`)은 폴더 위치가 바뀌면 깨짐.
- 스크립트는 항상 **저장소 루트에서** `node _스크립트/xxx.mjs`로 실행.

> 전 회차 공통 상세 원칙: `.kiro/steering/작업-원칙.md`
> 회차별 세부 지침: `_작업소스/{회차}/데이터/{회차}_작업지침.md`
