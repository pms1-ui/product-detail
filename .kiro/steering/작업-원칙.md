# 카카오 톡딜 상세페이지 작업 원칙 (전 회차 공통, 필수 준수)

이 프로젝트는 회차별(예: 260806, 260903, 260911 ...)로 카카오 톡딜 묶음상품 상세페이지를 제작한다.
아래 원칙은 **모든 회차에 예외 없이** 적용된다.

## 회차 폴더 구조 (표준, 항상 이 5개 폴더 생성)

새 회차를 시작하면 `_작업소스/{회차}/` 안에 아래 5개 폴더가 항상 만들어진다.

| 폴더 | 내용 | 채우는 주체 | 서버 업로드 대상 |
|---|---|---|---|
| `기초데이터/` | 상품 엑셀(`상품데이터*.xlsx`), 행사내용 md | 디자이너(현업 정리) | ✕ |
| `누끼컷&사은품/` | 상품 누끼컷(바닥컷) + `사은품/` 하위폴더 | 디자이너(현업 수령) | ✕ (소스) |
| `메인&카드 캡처결과/` | 상단 `01~04.jpg` + `cards/{NN}.jpg` | 에이전트(capture 자동) | ○ card/ 및 상단 |
| `상세이미지/` | 피그마 품번별 상세 이미지 `{순서}_{품번}.jpg` | 디자이너(피그마) | ○ detail_image/ |
| `상품상세html/` | 엑셀기반 품번별 상세 html `{순서}_{품번}.html` | 에이전트(자동 생성) | ○ kakao_detail/ |

- 그 외 회차 폴더 직속 파일: `작업용.html`(원본), `main-image.jpg`(메인 배경), `kakao_final_{회차}.html/.txt`(카카오 붙여넣기 소스).
- **경로/폴더명 규칙 고정**: 스크립트가 이 폴더명을 하드코딩으로 참조하므로 폴더명을 바꾸면 스크립트가 깨진다.

### 스크립트 경로 매핑 (회차 스크립트 작성 시 기준)
- 엑셀 읽기: `_작업소스/{회차}/기초데이터/상품데이터*.xlsx`
- 카드/사은품 이미지 소스(작업용.html의 `src`): `누끼컷&사은품/` (사은품은 `누끼컷&사은품/사은품/`)
- 캡처 출력: `_작업소스/{회차}/메인&카드 캡처결과/` (+ `cards/`)
- 상세 html 출력: `_작업소스/{회차}/상품상세html/`
- 상세 이미지(피그마): `_작업소스/{회차}/상세이미지/` → 서버 `detail_image/`

### 서버(S3) 업로드 매핑
- `메인&카드 캡처결과/cards/{NN}.jpg` → `{서버폴더}/card/{NN}.jpg`
- `메인&카드 캡처결과/01~04.jpg` → `{서버폴더}/` 바로 밑
- `상세이미지/{순서}_{품번}.jpg` → `{서버폴더}/detail_image/`
- `상품상세html/{순서}_{품번}.html` → `{서버폴더}/kakao_detail/`
- 상세이미지·상세html·카드 링크의 파일명 규칙은 모두 **`{순서}_{품번}`** 로 통일한다.

## 핵심 원칙: 생성과 수정을 분리한다

작업은 두 단계로 나뉘며, 절대 섞지 않는다.

### 1단계 — 최초 생성 (회차 시작 시 딱 1회)
- 엑셀 데이터를 기반으로 generate 스크립트를 실행해 `작업용.html`을 통째로 생성한다.
- 엑셀 파일과 generate 스크립트는 **회차마다 다르다** (파일명, 컬럼 구조, 로직이 바뀔 수 있음).
- 이 단계는 회차당 한 번만 수행한다.

### 2단계 — 부분 수정 (요청이 올 때마다)
- 사용자가 "구성 N번 상품명/가격/이미지/컬러 수정" 같은 개별 수정을 요청하면:
  - **generate 스크립트를 절대 다시 실행하지 않는다.** (재실행하면 그동안의 수동 수정이 전부 사라짐)
  - `작업용.html`을 **직접 편집**한다.
  - 요청받은 그 부분(그 카드)만 수정한다. 다른 카드는 건드리지 않는다.
  - 수정한 카드를 포함해 캡쳐 스크립트로 `_작업소스/{회차}/메인&카드 캡처결과/cards/*.jpg`를 재생성한다.
  - 로컬 확인용 프리뷰(`미리보기/{회차}_로컬확인.html`)를 열어 확인한다.

## 하지 말아야 할 것

- ❌ 부분 수정 요청에 generate 스크립트(엑셀 재생성)를 다시 돌리기 → 수동 수정분 유실
- ❌ 특정 카드 예외처리 로직을 generate 스크립트에 박아넣기 (예: "구성4는 NEW 빼기")
  → 엑셀·스크립트·수동수정이 뒤엉켜 source of truth가 불명확해짐
  → 예외는 스크립트가 아니라 `작업용.html`에서 직접 처리한다
- ❌ 엑셀을 기준으로 "다른 카드도 맞춰서" 함께 수정하기 → 요청 범위를 넘지 말 것

## Source of Truth

- 최초 생성 직후: 엑셀 = 원본
- 부분 수정이 시작된 이후: **`작업용.html`이 최신 원본**이다.
  수동 수정분은 엑셀에 없을 수 있으며, 이것이 정상이다.

## 수정 시 주의 (중복 텍스트)

- 상품명·가격 텍스트가 여러 카드에 중복될 수 있다.
- 단순 문자열 치환은 엉뚱한 카드를 바꿀 위험이 있으므로,
  반드시 **구성 번호("구성 NN") 위치를 기준으로 해당 카드 블록 안에서만** 수정한다.

## 표준 파이프라인 요약

```
[기초데이터/엑셀] --(generate, 회차당 1회)--> [_작업소스/{회차}/작업용.html] --(capture)--> [_작업소스/{회차}/메인&카드 캡처결과/cards/*.jpg] --(S3 업로드)--> 실서비스/미리보기
                                                        ▲
                                           부분 수정은 여기를 직접 편집
```

## 배포 전 필수 체크리스트 (S3 업로드/커밋 전에 항상 확인)

업로드하거나 커밋하기 전에 **반드시 아래를 확인한다.** 특히 상품이 추가/삭제된 회차에서 누락이 잦다.

1. **상품 수 일치 확인** — 아래가 전부 같은 개수인지 대조한다.
   - 엑셀 구성 수 = `작업용.html`의 "구성 NN" 수 = `cards/*.jpg` 수
     = `상품상세html/*.html` 수 = `상세이미지/*.jpg` 수
     = `kakao_final_{회차}.txt`/`.html`의 카드 수
     = `미리보기/{회차}_카카오톡딜.html`·`{회차}_로컬확인.html`의 카드 수
     = `index.html`의 해당 회차 "N개 구성" 표기
2. **미리보기 갱신 확인** — 카드가 바뀌었으면 아래 3개가 **모두** 새 개수로 갱신됐는지 본다.
   (한 곳만 갱신하고 나머지를 빠뜨리는 실수가 잦음)
   - `미리보기/{회차}_로컬확인.html` (로컬 이미지 참조)
   - `미리보기/{회차}_카카오톡딜.html` (S3 참조, **네틀리파이 배포 대상**)
   - `index.html`의 해당 회차 카드 메타("N회차 · N개 구성")
3. **카드 링크 ↔ 상세html 파일명 일치** — `card/{NN}` ↔ `kakao_detail/{순서}_{품번}.html` 매핑이 어긋나지 않는지 확인(404 방지).
4. 위 3가지는 `gen_kakao_final` 스크립트가 로컬확인·카카오톡딜 미리보기를 함께 생성하므로, 카드 재생성 시 이 스크립트를 돌려 자동 동기화한다. `index.html`은 수동 갱신 대상이므로 잊지 말 것.

## 배포 (S3 업로드)

- 부분 수정 후 실제 반영에 필요한 것은 보통 **`_작업소스/{회차}/메인&카드 캡처결과/cards/` 폴더(카드 이미지)뿐**이다.
- 상세 HTML/상세 이미지는 내용 변경이 없으면 다시 올리지 않는다.
- 상세 이미지(`detail_image/`)는 기존 S3 파일을 재사용한다 (새로 올리지 않음).

## 품절임박 딱지 (재사용 표준)

품절 임박 상품 카드에 붙이는 빨간 아웃라인 딱지. 260903 회차에서 처음 도입.

### 표시 규칙
- **NEW 딱지가 있는 카드** → 품절임박은 NEW **아래**에 배치.
- **NEW 딱지가 없는 카드** → NEW 자리인 **좌상단(top:10px; left:10px)**에 배치.
- 대상은 반드시 **화면의 "구성 NN" 텍스트 기준**으로 찾는다.
  (상품이미지 파일명 앞 숫자와 구성번호가 다를 수 있음 — 카드 삭제/재번호된 회차 주의)

### 스타일 스펙 (그대로 복붙해서 재현)
- 배경: 반투명 흰색 `rgba(255,255,255,0.6)` (거의 투명, 아웃라인 스타일)
- 테두리: `1.9px solid #FF3B30` (빨강)
- 글자색: `#FF3B30` (빨강)
- 폰트: `Pretendard, sans-serif`, `font-size:17.5px`, `font-weight:800`
- 안쪽 여백: `padding:5px 12.5px`, 모서리 `border-radius:8.75px`
- 불꽃 아이콘: `누끼컷&사은품/fire.png` (검은 불꽃 원본을 빨강+투명 변환한 것), `width/height 16.25px`
  - 원본 검은 아이콘: `_작업소스/공용에셋/fire.png`
  - 빨강 변환본: `_작업소스/공용에셋/fire_red.png` (캡처용으로 회차 `누끼컷&사은품/fire.png`에 복사해 사용)
- 아이콘과 글자 간격: `gap:5px`, 세로 정렬 `align-items:center`
- 레이어: `position:absolute; z-index:3`

### HTML 스니펫
```html
<div style="position:absolute; top:10px; left:10px; background:rgba(255,255,255,0.6); border:1.9px solid #FF3B30; color:#FF3B30; font-family:Pretendard,sans-serif; font-size:17.5px; font-weight:800; padding:5px 12.5px; border-radius:8.75px; z-index:3; display:flex; align-items:center; gap:5px;"><img src="누끼컷&사은품/fire.png" style="width:16.25px; height:16.25px; display:block; flex-shrink:0; object-fit:contain;">품절임박</div>
```

> 삽입 위치: 각 카드의 이미지 영역(`position:relative`인 div) 안, 그 카드의 상품 `<img>` 바로 앞.
> 여러 카드에 중복 문자열이 있으므로, 삽입 앵커는 각 카드의 **고유 상품 누끼컷 파일명**을 사용한다.
> 삽입 후 반드시 capture 스크립트로 재캡처 → 대상 카드 이미지에 딱지가 구워진다.
